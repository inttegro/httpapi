## What you define once

An endpoint can carry its method and route, request parser, response shapes, caller access, authorization mode, idempotency, request limits, timeouts, and operation metadata.

HTTPAPI uses that definition to:

- reject unacceptable requests before the handler runs;
- expose only response fields available to the active caller;
- record a consistent completion outcome; and
- transcribe the mounted API without a second handwritten schema.

## What stays in your service

Your application still owns identity verification, domain authorization, databases, transactions, business workflows, observability backends, and deployment. HTTPAPI provides explicit interfaces where those systems meet the HTTP boundary.

<Note>
  These guides document the Go reference implementation. The [HTTPAPI 0.2 specification](/specification/v0.2) defines portable observable behavior and is authoritative for conformance.
</Note>
